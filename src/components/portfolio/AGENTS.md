# Portfolio component rules

- Both edit tables render selected fields in saved key order through column-order; ColumnChooser uses handle-only pointer/keyboard sorting and the existing per-account device storage, so field visibility and order stay together without writing CRM data.

- Edit tables filter and sort from their column headers (table/ColumnHeaderMenu + pure src/lib/table-filter.ts): pick-list columns tick values (multi-select cells match any value, blanks filterable), free-text columns use "contains", and each column's value list reflects the other active filters — no separate filter dropdowns above the table.
- Workstream Dell Stakeholders stay a comma-separated name list (every other reader parses that text); the edit table links names to Network people at read time via src/lib/workstream-stakeholders.ts (exact full name or email only, Dell record wins a same-name tie, anything else stays unlinked for a human to pick) and person edits go through the shared people-finder/updatePersonFn paths — no stored IDs to drift from the sheet.
- Dell statuses stored on both each workstream and the company profile (Sell With Dell Status: multi-choice on both; Sell-In Status: one choice per workstream, multi on the company) share the pure sync rules in src/lib/status-sync.ts, wired through SYNCED_STATUS in portco-store.server: the company always holds every status its workstreams hold (read-time merge repairs a missed sync) and may hold company-wide extras; workstream changes update the company, company removals clear matching workstreams, and company edits merge as added/removed statuses — both views stay consistent without conflicts.
