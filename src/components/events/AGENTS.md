- Event PortCo tags are stored and shown only as official Portfolio Companies names (src/lib/event-portcos.ts; approved aliases live there); every Events DB write canonicalizes and company Events tabs read the Events DB first, with Asana filling gaps — Asana spellings otherwise duplicate companies per event.
- Contact event tags join event attendee lists only via the pure attendance-reconcile planner (approved appends) or the import picker writing by planner URID — prevents name drift.
- Event pickers offer only Event Tracker events (merged older names searchable, canonical name stored; "no event" is an explicit choice) and every person-event write canonicalizes through canonicalTrackerEventName, rejecting unknown names — typed or Asana-only names used to strand attendees outside the tracker.
- Event detail people/campaigns come from pure src/lib/event-people.ts: tracker attendees + Network and Prospecting tags + raw tags for people not in the CRM, matched on canonical/merged names with years kept — so prospects show and different editions never mix.
- Planner rows come from pure helpers in src/lib/event-planner.ts (plannerCategories, placementRow): Potential/uncategorized events sit in the bottom Potential row and DTC Status Considering or later lifts them into their category row; retired category/status labels are mapped on read (canonicalSubcategory/canonicalDtcStatus) so old sheet rows never strand.
- Partner categories broken out from the Partners list live in the Event Tracker "Planner Partners" tab (Removed At retires one; its events fall back to Other); the side panel collects edits in a draft and saves only changed fields (src/lib/event-draft.ts) on Save, on close or before opening another event, so one write carries the Updated stamp and nothing half-saves.
- Event Partner tags and the Partner filter use only Partners-tab names (shared "partner-names" query); legacy unmatched tags show flagged until removed — keeps partner spellings identical to the Partners page.
- Event partners: the first Partners tag is the primary owner. Partner-led has no fixed partner categories (only Other); in partner rows the shown category is derived at read time by effectiveCategory (fetchPlannerFn and the grid preview), and editors use categoryAfterPartnerChange — so tagging or adding a partner row recolours events without rewriting sheet rows; DTC-led events never move.
